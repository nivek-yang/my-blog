深入理解新一代安全架構「零信任 (Zero Trust)」

發表於 2025-10-07 分類於 技術筆記

讓我們來談談一個經典的安全模型：城堡與護城河 (Castle-and-Moat)。數十年來，企業網路安全幾乎都建立在這個模型之上。我們耗費巨資建造了堅固的「城牆」（防火牆）、挖掘了深邃的「護城河」（入侵檢測系統），並在唯一的「吊橋」（VPN）上設置了森嚴的守衛。

這個模型的假設很簡單：牆外是危險的，牆內是安全的。 只要能通過驗證進入內部網路，就會被視為「受信任的」員工，可以在城堡內部相對自由地活動。

然而，在雲端服務、遠距辦公和行動裝置已成主流的今天，這座城堡的邊界早已模糊不清。當員工在咖啡廳用著個人筆電存取雲端 SaaS 服務時，「牆內」和「牆外」的區別在哪裡？更致命的是，一旦攻擊者（或內部威脅）通過釣魚郵件等方式騙取了 VPN 憑證，就等於直接越過了護城河，整個城堡的內部將暢行無阻。

這個過時的信任模型，正是「零信任 (Zero Trust)」架構要徹底顛覆的對象。

什麼是 Zero Trust？

Zero Trust（零信任） 是一種 網路安全架構理念，核心思想是：
👉 不要預設信任任何人或任何設備，不論它們在網路內部還是外部，每次存取資源都必須驗證。

Zero Trust 不是一個產品，也不是一套工具，而是一種安全策略和思維框架。它由前 Forrester 分析師 John Kindervag 在 2010 年提出，其核心理念極其簡單，卻又極具顛覆性：

Never Trust, Always Verify. (永不信任，一律驗證)

這意味著，我們必須拋棄傳統安全模型「公司內網可信，外網不可信」的二元假設。在零信任模型中，預設沒有任何使用者、裝置或網路流量是可信的——無論它來自內部網路還是外部網路。 每一次的存取請求，都必須像來自一個不受信任的網路一樣，經過嚴格的身份驗證、授權和加密，才能被放行。

簡單比喻：

  • 傳統模型： 像一個鄉村俱樂部。只要是會員（通過了 VPN 認證），進門後就可以自由使用所有設施。
  • 零信任模型： 像一棟高度機密的政府大樓。刷卡進入大門後，要去 A 房間需要再次刷卡驗證；要去 B 檔案室，不僅要刷卡，可能還需要指紋和虹膜掃描。每一次穿越一道門，都需要重新證明身份和權限。

在 Zero Trust 模型下：

  • 沒有「安全區域」的概念。
  • 所有存取都需要 驗證 (Verify) 與 授權 (Authorize)。

為什麼需要 Zero Trust？

傳統的安全模式（perimeter-based, 邊界防禦）存在問題：

  1. VPN/內網突破：一旦駭客進入內網，就能存取大量資源。
  2. 雲端與遠端工作普及：使用者可能來自不同地點與裝置。
  3. 內部威脅：員工或受感染的設備也可能帶來風險。

Zero Trust 用來降低這些風險。

Zero Trust 的三大原則

  1. Verify Explicitly（明確驗證）

    每次存取都要驗證身分（MFA、多因素驗證）、裝置狀態、地理位置等。

    這是「一律驗證」的具體化。每一次的存取請求，都必須基於所有可用的數據點進行全面的驗證，包括：

    • 使用者身份： 是誰在請求？（強身份認證，如 MFA 多因子認證）
    • 裝置健康狀況： 請求來自哪個裝置？這個裝置是否合規、有沒有中毒？
    • 存取位置： 請求的地理位置是否正常？
    • 服務或工作負載： 他們正在嘗試存取什麼？
    • 數據分類： 正在被存取的數據是否敏感？

    只有綜合評估這些信號後，系統才會做出信任判斷。

  2. Least Privilege Access（最小權限存取）

    使用者或服務只擁有完成任務所需的最小權限，避免過度授權。

    這是「永不信任」的體現。一旦使用者通過驗證，也絕不給予他們完全的信任。他們只應被授予完成其特定任務所需的最小權限。

    • Just-in-Time (JIT) Access: 只在需要時才授予臨時權限，任務完成後立刻收回。
    • Just-Enough-Access (JEA): 權限範圍嚴格限制在必需的數據和資源上。
    • 目標： 大幅縮小潛在的攻擊面。即使某個帳號被盜，攻擊者能造成的破壞也被限制在一個極小的範圍內。

  3. Assume Breach（假設已被入侵）

    系統假設隨時可能被突破，並持續監控與分段隔離。

    這是一種防禦性的思維轉變。必須假設，攻擊者已經存在於我們的網路之內。基於這個假設，所做的一切設計都是為了：

    • 將爆炸半徑最小化： 通過微分段 (Micro-segmentation) 技術，將網路切分成許多微小的、相互隔離的區域。這樣，即使一個區域被攻破，攻擊者也無法輕易地橫向移動到其他區域。
    • 端到端加密： 確保所有網路流量，即使是內部流量，都經過加密。
    • 持續監控與分析： 利用分析工具持續監測網路活動，以便盡快偵測到威脅並做出反應。

Zero Trust 架構的關鍵元素

  • 身分驗證 (Identity Verification) → SSO、MFA
  • 裝置安全 (Device Security) → 僅允許合規裝置存取
  • 網路微分段 (Micro-segmentation) → 不同應用、服務之間要分隔
  • 持續監控 (Continuous Monitoring) → 偵測異常行為
  • 動態授權 (Adaptive Access Control) → 根據情境決定是否允許

簡單例子

傳統模式

  • 員工進入內網後，就能存取所有內部資源。
  • 駭客只要破解 VPN 或某台內部機器，就能橫向移動，拿到更多資料。

Zero Trust 模式

  • 員工登入公司雲端系統時，必須：

    1. 使用 MFA 驗證身份
    2. 驗證裝置是否安全（例如防毒軟體是否開啟）
    3. 僅授權該員工所需的應用（例如只能開 HR 系統，不能開財務系統）

  • 若異常行為（如短時間內嘗試大量下載檔案），會被即時阻擋。

常見 Zero Trust 技術

  • Identity & Access Management (IAM) → Okta, Azure AD
  • Multi-Factor Authentication (MFA)
  • Zero Trust Network Access (ZTNA) → 替代傳統 VPN
  • Endpoint Detection & Response (EDR) → CrowdStrike, SentinelOne

零信任不是一蹴可幾，而是一趟旅程

部署零信任架構並非購買一個工具就能完成。它是一個持續的過程，涉及到身份管理、端點安全、網路架構和應用程式等多個層面的整合與改造。一個務實的起步路徑可能包括：

  1. 從身份認證開始： 為所有員工和服務全面啟用 MFA（多因子認證）。
  2. 了解你的裝置： 建立裝置清單，監控其健康狀況。
  3. 實施微分段： 從最關鍵的應用程式或數據周圍開始，建立小型的安全區域。
  4. 重新評估權限： 審查現有權限，並朝著最小權限原則進行改革。

總結

Zero Trust = 不預設信任任何人或設備 → 每次存取都必須驗證、授權、監控。
它的目標是減少內外部攻擊風險，適合 遠端工作、雲端環境、微服務架構 的現代企業。

它從根本上改變了我們的安全思維，從被動地防禦「外部」威脅，轉變為主動地管理「內部」風險。
通過擁抱「永不信任，一律驗證」的原則，我們將能構建更有彈性、更能適應未來挑戰的安全體系。
