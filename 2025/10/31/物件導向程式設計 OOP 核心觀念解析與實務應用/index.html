物件導向程式設計 (OOP) 核心觀念解析與實務應用

發表於 2025-10-31 分類於 技術筆記

在現代軟體開發中，物件導向程式設計（Object-Oriented Programming, OOP）無疑是最主流的典範之一。它透過將現實世界的概念對映成程式碼中的「物件」，幫助我們建立更模組化、可擴充且易於維護的軟體。

本篇文章將深入探討 OOP 的四大核心概念：封裝、繼承、多型、抽象，並結合重要的設計原則和簡單的 Python CRUD 範例，帶你一窺 OOP 的奧妙。

四大核心概念

1. 封裝 (Encapsulation)

封裝是將物件的資料（屬性）和操作該資料的方法（行為）捆綁在一起的機制。這麼做的好處是隱藏物件內部的複雜實作細節，僅對外提供有限的介面（public methods）來進行互動。這就像操作一台微波爐，只需要按下按鈕（介面），而不需要理解內部的電路（實作細節）是如何運作的。

在 Python 中，通常使用 class 來實現封裝。雖然 Python 沒有像 Java 或 C++ 那樣的 private 關鍵字，但社群慣例會以單底線 _ 開頭的屬性或方法表示其為內部使用，不建議外部直接存取。

優點：

  • 安全性：保護資料不被外部程式任意修改。
  • 簡化複雜度：隱藏內部實作，讓物件更容易使用。
  • 提高可維護性：當內部實作需要修改時，只要公開介面不變，就不會影響到外部的程式碼。

2. 繼承 (Inheritance)

繼承允許一個類別（子類別）獲取另一個類別（父類別）的屬性和方法。這是一種實現程式碼重用（code reuse）的強大機制。例如，「狗」和「貓」都可以繼承自「動物」類別，「狗」和「貓」將自動擁有「動物」的共同特徵（如：name, age）和行為（如：eat()），並可以各自擴充自己獨有的行為（如：bark() 或 meow()）。

優點：

  • 程式碼重用：父類別的功能可以被多個子類別共享，減少重複程式碼。
  • 建立層次結構：更清晰地表達類別之間的「is-a」（是一種）關係。

3. 多型 (Polymorphism)

多型的字面意思是「多種型態」。在 OOP 中，它指的是不同的物件可以使用相同的方法名稱，但會根據物件本身的型別而產生不同的行為。換句話說，父類別定義一個介面，讓不同的子類別用自己的方式去實現它。

例如，Animal 類別有一個 make_sound() 方法，「狗」物件呼叫時會發出「汪汪」聲，而「貓」物件呼叫時則發出「喵喵」聲。這就是多型。

優點：

  • 彈性與擴充性：可以輕易地加入新的子類別，而不需要修改呼叫端的程式碼。
  • 簡化程式邏輯：可以對一群不同型別的物件執行相同的操作，程式碼更簡潔。

4. 抽象 (Abstraction)

抽象專注於物件的必要特徵，而忽略不重要的細節。它透過定義抽象類別（Abstract Base Class, ABC）或介面（Interface）來規範一組子類別必須實現的方法。抽象類別本身通常不能被實例化，它的存在是為了被繼承。

例如，可以定義一個抽象的 Shape 類別，並宣告一個 calculate_area() 的抽象方法。任何繼承自 Shape 的具體類別（如 Circle, Square）都必須實作自己的 calculate_area() 方法，否則程式會報錯。

優點：

  • 定義規範：確保所有相關的子類別都具備某些必要的功能。
  • 降低耦合度：程式可以依賴於抽象介面，而不是具體的實作，使得系統更加靈活。

重要的設計原則 - SOLID

除了四大核心概念，遵循良好的設計原則能讓 OOP 程式碼品質更上一層樓。SOLID 是五個基本原則的縮寫：

  • S - 單一職責原則 (Single Responsibility Principle)：一個類別應該只有一個引起它變更的原因。
  • O - 開放封閉原則 (Open/Closed Principle)：軟體實體（類別、模組、函式）應該對擴充開放，對修改封閉。
  • L - 里氏替換原則 (Liskov Substitution Principle)：子類別物件必須能夠替換掉任何父類別物件，而不會產生錯誤。
  • I - 介面隔離原則 (Interface Segregation Principle)：客戶端不應該被迫依賴它不需要的介面。
  • D - 依賴反轉原則 (Dependency Inversion Principle)：高階模組不應該依賴於低階模組，兩者都應該依賴於抽象。

遵循這些原則，可以讓系統更加健壯、靈活且易於維護。

Python CRUD 實務範例

接下來，用一個簡單的使用者管理系統來展示這些概念如何實際應用。這個系統將提供基本的建立（Create）、讀取（Read）、更新（Update）和刪除（Delete）功能。

from abc import ABC, abstractmethod

# --- 4. 抽象 (Abstraction) ---
# 定義一個資料儲存的抽象類別，規範所有儲存方式都必須有 CRUD 方法
class UserRepository(ABC):
    @abstractmethod
    def add(self, user):
        pass

    @abstractmethod
    def get(self, user_id):
        pass

    @abstractmethod
    def get_all(self):
        pass

    @abstractmethod
    def update(self, user):
        pass

    @abstractmethod
    def delete(self, user_id):
        pass

# --- 1. 封裝 (Encapsulation) ---
# 使用者類別，封裝了使用者的屬性和行為
class User:
    def __init__(self, user_id, name, email):
        self._user_id = user_id  # 使用底線表示內部屬性
        self._name = name
        self._email = email

    # 提供公開的 getter 方法來存取資料
    @property
    def user_id(self):
        return self._user_id

    @property
    def name(self):
        return self._name

    @name.setter
    def name(self, value):
        if value:
            self._name = value
        else:
            print("Name cannot be empty.")

    @property
    def email(self):
        return self._email

    @email.setter
    def email(self, value):
        if "@" in value:
            self._email = value
        else:
            print("Invalid email format.")
          
    def __str__(self):
        return f"User(ID: {self.user_id}, Name: {self.name}, Email: {self.email})"

# --- 2. 繼承 (Inheritance) & 3. 多型 (Polymorphism) ---
# 實作一個基於記憶體字典的儲存庫
# 它繼承了 UserRepository，並提供了具體的 CRUD 方法實作
class InMemoryUserRepository(UserRepository):
    def __init__(self):
        self._users = {}

    def add(self, user):
        if user.user_id in self._users:
            print(f"Error: User with ID {user.user_id} already exists.")
            return
        self._users[user.user_id] = user
        print(f"User {user.name} added.")

    def get(self, user_id):
        return self._users.get(user_id)

    def get_all(self):
        return list(self._users.values())

    def update(self, user):
        if user.user_id in self._users:
            self._users[user.user_id] = user
            print(f"User {user.name} updated.")
        else:
            print(f"Error: User with ID {user.user_id} not found.")

    def delete(self, user_id):
        if user_id in self._users:
            del self._users[user_id]
            print(f"User with ID {user_id} deleted.")
        else:
            print(f"Error: User with ID {user_id} not found.")

# ---- 主程式：實際應用 ----
if __name__ == "__main__":
    # 多型的應用：宣告變數的型別是抽象的 UserRepository
    # 但實際賦予它的是具體的 InMemoryUserRepository 實例
    # 這符合依賴反轉原則：依賴於抽象，而非具體實現
    repo: UserRepository = InMemoryUserRepository()

    # Create
    user1 = User(1, "Alice", "alice@example.com")
    user2 = User(2, "Bob", "bob@example.com")
    repo.add(user1)
    repo.add(user2)
    print("-" * 20)

    # Read
    print("All users:")
    for user in repo.get_all():
        print(user)
    print("-" * 20)
  
    retrieved_user = repo.get(1)
    print(f"Retrieved user: {retrieved_user}")
    print("-" * 20)

    # Update
    if retrieved_user:
        retrieved_user.name = "Alice Smith"
        repo.update(retrieved_user)
  
    updated_user = repo.get(1)
    print(f"Updated user name: {updated_user.name}")
    print("-" * 20)

    # Delete
    repo.delete(2)
    print("All users after deletion:")
    for user in repo.get_all():
        print(user)

範例解析：

  1. 抽象：UserRepository 是一個抽象基礎類別，它定義了所有使用者儲存庫應該具備的功能，但沒有提供任何實作。這為系統設立了一個標準契約。
  2. 繼承：InMemoryUserRepository 繼承自 UserRepository，並提供了所有抽象方法的具體實作。未來如果想改用資料庫儲存（例如 PostgresUserRepository），只需要再建立一個新的類別繼承 UserRepository 即可，符合開放封閉原則。
  3. 封裝：User 類別將 _user_id, _name, _email 等資料封裝起來。外部程式碼只能透過 @property 裝飾的 getter 和 setter 來讀取或修改這些資料，並在 setter 中加入了簡單的驗證邏輯。
  4. 多型：在主程式中，變數 repo 的型別是抽象的 UserRepository，但它實際指向一個 InMemoryUserRepository 的實例。這使得程式碼更加靈活。如果未來換成資料庫實作，主程式的邏輯完全不需要更動。

結論

物件導向程式設計不僅僅是學習如何寫 class，更重要的是理解其背後的四大核心概念與設計原則。透過封裝保護資料、繼承重用程式碼、多型增加彈性、抽象定義規範，可以建構出結構清晰、易於擴充且穩健的軟體系統。
