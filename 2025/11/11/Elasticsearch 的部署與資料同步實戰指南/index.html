Elasticsearch 的部署與資料同步實戰指南

發表於 2025-11-11 分類於 技術筆記

在上一篇文章 《解密 Elasticsearch：不只是全文搜尋，更是強大的數據分析引擎》已經了解了 Elasticsearch 的強大之處，也透過 cURL 或 Kibana 執行了幾個基本的 CRUD 操作。這時，一個關鍵的問題浮現腦海：「在真實的專案中，該如何部署 Elasticsearch？又要如何讓現有資料庫的資料跑到 Elasticsearch 裡面去？」

本篇文章將深入探討兩個核心主題：

  1. 環境建置：從本機開發到生產環境，選擇最適合的部署策略。
  2. 資料同步：探討將資料從主資料庫（如 SQL）導入 Elasticsearch 的主流架構與最佳實踐。

建置 Elasticsearch 叢集

部署 Elasticsearch 從來不是「one-size-fits-all」。目標是快速原型開發，還是建立一個穩如磐石的生產系統，將決定你選擇的道路。

在本機 (Local) 開發：擁抱 Docker Compose

在開發階段，追求的是速度、一致性與隔離性。沒有什麼比 Docker Compose 更適合這個任務了，用一個設定檔，就能一鍵啟動 Elasticsearch、Kibana 以及未來可能需要的任何相依服務。

最佳實踐： 使用 Docker Compose 將環境容器化。

  • 為何選擇它？
    • 環境一致性：告別「在我電腦上可以跑」的窘境，確保團隊成員使用完全相同的環境。
    • 快速啟動與銷毀：docker compose up 啟動所有服務，docker compose down -v 徹底清除，不留任何殘跡。
    • 版本控制：在 YAML 檔中輕鬆切換 Elasticsearch 版本，進行相容性測試。

docker-compose.yml 範例：

version: '3.7'
services:
  # Elasticsearch 服務
  elasticsearch:
    image: docker.elastic.co/elasticsearch/elasticsearch:8.11.1 # 明確指定版本
    container_name: es01
    environment:
      # 設定為單節點模式
      - discovery.type=single-node
      # 開發時可關閉安全驗證以求方便，生產環境切勿如此
      - xpack.security.enabled=false
    ports:
      - "9200:9200" # REST API
      - "9300:9300" # 內部節點通訊
    volumes:
      - es_data:/usr/share/elasticsearch/data

  # Kibana 服務
  kibana:
    image: docker.elastic.co/kibana/kibana:8.11.1
    container_name: kibana01
    ports:
      - "5601:5601"
    depends_on:
      - elasticsearch # 確保 ES 啟動後再啟動 Kibana

# Docker Volume，用於持久化 ES 資料
volumes:
  es_data:

將以上內容存為 docker-compose.yml，在本機執行 docker compose up，一個完整的開發環境就緒了。

在生產 (Production) 環境部署

生產環境的關鍵詞是：高可用、可擴展、安全、易於維護。除非有一個經驗豐富的 SRE/DevOps 團隊，否則自建維運叢集將會是一場惡夢。

最佳實踐： 優先選擇託管服務 (Managed Service)。

將叢集的監控、備份、升級、擴展等繁重工作，交給最了解 Elasticsearch 的專家。

  1. Elastic Cloud：官方提供的服務，功能最完整，與最新版本同步，並提供專業技術支援。支援部署在 AWS, GCP, Azure。
  2. 雲端供應商服務：如 AWS OpenSearch Service、GCP 的 Elasticsearch Service 等。優點是與該雲端平台的生態系整合度高。

次要選擇：自建 (Self-Hosted)
僅在特殊合規要求或內部技術力雄厚時考慮。

  • 在 Kubernetes 上部署 (ECK Operator)：這是現代自建的首選。Elastic 官方提供的 ECK Operator 能大幅簡化在 K8s 上部署、管理和升級的複雜度。
  • 在虛擬機/實體機上部署：使用 Ansible, Terraform 等自動化工具進行部署。需要投入大量心力處理叢集維運的各種細節。

從資料庫到 Elasticsearch 的同步策略

「需要把整個資料庫都同步過去嗎？」

答案是：千萬不要！

請牢記這個核心架構原則：主資料庫（SQL DB）是「唯一真實來源 (Source of Truth)」，而 Elasticsearch 是為了特定目的（搜尋、分析）建立的「特化索引 (Specialized Index)」。

只需要將需要被搜尋和分析的資料子集同步過去。例如，商品的名稱、描述、分類、價格，絕不是使用者的密碼雜湊值或內部的訂單狀態碼。

如何實現資料同步？

資料同步的方案眾多，從簡單到複雜，以下是三種主流方案的權衡：

方案一：定時批次處理 (Batch Polling)

寫一個排程任務（Cron Job），每隔幾分鐘就去掃描資料庫，找出異動的資料，然後批次更新到 Elasticsearch。

  • 優點：實現相對簡單。
  • 缺點：延遲性高、對主資料庫效能衝擊大。不適合需要即時搜尋的場景。

方案二：應用程式雙寫 (Dual Writes)

在應用程式程式碼中，當更新資料庫後，立刻再發一個請求去更新 Elasticsearch。

  • 優點：邏輯直觀。
  • 缺點：資料一致性的惡夢。如果資料庫寫入成功，但 Elasticsearch 寫入失敗怎麼辦？處理這種分散式交易的複雜度非常高，容易造成兩邊資料不一致。

方案三：變更資料擷取 (Change Data Capture, CDC) - 最佳實踐

這是現代系統中最可靠、高效的方案。它不去「查詢」資料庫，而是去「監聽」資料庫的交易日誌 (Transaction Log，如 MySQL 的 Binlog)。任何資料的改動都會被即時捕捉。

  • 典型架構：
    資料庫 Log -> Debezium -> Kafka -> Logstash/Consumer -> Elasticsearch

  • 優點：

    • 近乎即時：從資料變更到可被搜尋，延遲通常在毫秒或秒級。
    • 高可靠性：基於交易日誌，確保不會遺漏任何變更。
    • 完全解耦：同步邏輯與主應用程式完全分離，對主資料庫效能影響極小。

  • 缺點：架構較複雜，需要引入 Debezium、Kafka 等額外元件。但對於嚴謹的生產系統而言，這份前期投入是絕對值得的。

實戰演練 - 用 Python 與 Docker Compose 打造全文搜尋

用一個具體的技術棧——Python (FastAPI)、PostgreSQL、Elasticsearch 來搭建一個文章搜尋服務。將使用 Docker Compose 來管理整個環境，並採用「應用程式雙寫」這種相對簡單的方式來進行資料同步，非常適合原型開發和快速驗證。

Step 1: 專案結構與 Docker Compose 設定

建立專案結構：

fulltext-search-demo/
├── app/
│   ├── main.py         # FastAPI 應用程式
│   ├── database.py     # 資料庫連線設定
│   ├── models.py       # SQLAlchemy 模型
│   └── es_client.py    # Elasticsearch 客戶端
├── docker-compose.yml  # 環境定義檔
└── requirements.txt    # Python 依賴

requirements.txt

fastapi
uvicorn[standard]
sqlalchemy
psycopg2-binary
elasticsearch

docker-compose.yml
這份設定檔是整個專案的核心。它定義了四個服務：Python 應用、PostgreSQL 資料庫、Elasticsearch 和 Kibana。

version: '3.8'
services:
  # Python FastAPI 應用程式
  api:
    build: .
    container_name: search_api
    command: uvicorn app.main:app --host 0.0.0.0 --port 8000 --reload
    volumes:
      - ./app:/app
    ports:
      - "8000:8000"
    depends_on:
      - db
      - elasticsearch

  # PostgreSQL 資料庫 (Source of Truth)
  db:
    image: postgres:14
    container_name: postgres_db
    environment:
      - POSTGRES_USER=user
      - POSTGRES_PASSWORD=password
      - POSTGRES_DB=blogdb
    volumes:
      - postgres_data:/var/lib/postgresql/data
    ports:
      - "5432:5432"

  # Elasticsearch 服務
  elasticsearch:
    image: docker.elastic.co/elasticsearch/elasticsearch:8.11.1
    container_name: es01
    environment:
      - discovery.type=single-node
      - xpack.security.enabled=false
      - ELASTIC_PASSWORD=changeme # 即使安全關閉，也最好設定
    ports:
      - "9200:9200"
    volumes:
      - es_data:/usr/share/elasticsearch/data

  # Kibana 服務 (可選，但強烈推薦)
  kibana:
    image: docker.elastic.co/kibana/kibana:8.11.1
    container_name: kibana01
    ports:
      - "5601:5601"
    depends_on:
      - elasticsearch

volumes:
  postgres_data:
  es_data:

FROM python:3.9-slim

Step 2: 撰寫 Python 應用程式

現在來填充 app/ 目錄下的 Python 檔案。

database.py - 設定 PostgreSQL 連線

from sqlalchemy import create_engine
from sqlalchemy.ext.declarative import declarative_base
from sqlalchemy.orm import sessionmaker

DATABASE_URL = "postgresql://user:password@db/blogdb"

engine = create_engine(DATABASE_URL)
SessionLocal = sessionmaker(autocommit=False, autoflush=False, bind=engine)
Base = declarative_base()

def get_db():
    db = SessionLocal()
    try:
        yield db
    finally:
        db.close()

models.py - 定義我們的文章模型

from sqlalchemy import Column, Integer, String, Text
from .database import Base

class Article(Base):
    __tablename__ = "articles"
    id = Column(Integer, primary_key=True, index=True)
    title = Column(String, index=True)
    content = Column(Text)

es_client.py - 設定 Elasticsearch 連線

from elasticsearch import Elasticsearch

# 連接到 Docker Compose 中定義的 elasticsearch 服務
es = Elasticsearch("http://elasticsearch:9200")

INDEX_NAME = "articles"

def create_es_index():
    """如果索引不存在，則建立它"""
    if not es.indices.exists(index=INDEX_NAME):
        es.indices.create(index=INDEX_NAME)
        print(f"Index '{INDEX_NAME}' created.")

main.py - 應用程式主邏輯 (FastAPI)
這是最關鍵的部分。將實現兩個主要功能：

  1. 建立文章：同時寫入 PostgreSQL 和 Elasticsearch (雙寫)。
  2. 搜尋文章：從 Elasticsearch 中進行全文搜尋。
from fastapi import FastAPI, Depends, HTTPException
from sqlalchemy.orm import Session
from typing import List

from . import models, es_client
from .database import engine, get_db

# 建立資料庫表格
models.Base.metadata.create_all(bind=engine)

app = FastAPI()

@app.on_event("startup")
def on_startup():
    # 應用啟動時確保 Elasticsearch 索引存在
    es_client.create_es_index()

# --- API Endpoints ---

@app.post("/articles/")
def create_article(title: str, content: str, db: Session = Depends(get_db)):
    """
    建立新文章：同時寫入 PostgreSQL 和 Elasticsearch
    """
    # 1. 寫入 PostgreSQL (Source of Truth)
    db_article = models.Article(title=title, content=content)
    db.add(db_article)
    db.commit()
    db.refresh(db_article)

    # 2. 寫入 Elasticsearch
    es_doc = {
        "db_id": db_article.id,
        "title": db_article.title,
        "content": db_article.content
    }
    es_client.es.index(index=es_client.INDEX_NAME, id=db_article.id, document=es_doc)
  
    return {"message": "Article created successfully", "article_id": db_article.id}

@app.get("/search/")
def search_articles(q: str):
    """
    從 Elasticsearch 進行全文搜尋
    """
    if not q:
        return {"results": []}

    # 使用 match query 進行全文搜尋
    query = {
        "query": {
            "multi_match": {
                "query": q,
                "fields": ["title", "content"]
            }
        }
    }
  
    response = es_client.es.search(index=es_client.INDEX_NAME, body=query)
  
    # 整理回傳結果
    hits = [hit['_source'] for hit in response['hits']['hits']]
    return {"results": hits}

Step 3: 啟動並測試

  1. 在專案根目錄下，執行 docker compose up --build。Docker 將會建置 Python 映像檔並啟動所有四個容器。
  2. 等待所有服務啟動完成。
  3. 建立文章：使用 curl 或 API 測試工具 (如 Postman) 呼叫 POST http://localhost:8000/articles/。
    curl -X POST "http://localhost:8000/articles/?title=Hello%20Elasticsearch&content=This%20is%20a%20test%20about%20the%20powerful%20search%20capabilities."

curl -X POST "http://localhost:8000/articles/?title=Python%20Best%20Practices&content=Learn%20how%20to%20write%20clean%20and%20efficient%20code."
  4. 驗證資料：
    • 可以連線到 PostgreSQL 查看 articles 表格中是否有資料。
    • 打開瀏覽器訪問 Kibana (http://localhost:5601)，使用開發工具 (Dev Tools) 查詢 Elasticsearch 中的資料：
      GET /articles/_search
  5. 進行搜尋：呼叫搜尋 API。
    # 搜尋 "powerful search"
curl "http://localhost:8000/search/?q=powerful%20search"
# 回傳第一篇文章

# 搜尋 "python code"
curl "http://localhost:8000/search/?q=python%20code"
# 回傳第二篇文章

這個範例展示了如何將多個服務整合在一起，並實現了核心的「雙寫」同步邏輯。雖然在生產環境中會選擇更穩健的 CDC 方案，但這個範例已經鋪平了通往全文搜尋功能的康莊大道。

結論

  1. 開發階段：採用 Docker Compose，享受快速迭代的便利。
  2. 生產部署：評估使用 Elastic Cloud 或其他託管服務，將寶貴時間專注在業務邏輯上，而非基礎設施的維運。
  3. 資料同步：將 SQL 資料庫視為「真實來源」，僅同步必要的資料子集。優先研究並導入基於 CDC（Change Data Capture）的同步架構，為應用提供最即時、最可靠的搜尋體驗。
