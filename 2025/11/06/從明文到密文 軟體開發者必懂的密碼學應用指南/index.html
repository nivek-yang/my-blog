從明文到密文：軟體開發者必懂的密碼學應用指南

發表於 2025-11-06 分類於 技術筆記

作為軟體開發者，我們不僅是功能的創造者，更是使用者資料的守護者。如何確保資料在儲存、傳輸的過程中不被竊取或竄改？答案就是密碼學 (Cryptography)。

本篇文章將走進密碼學的世界，從核心概念講起，用實際的 Python 程式碼展示三種關鍵的密碼學技術，並了解它們在真實世界中是如何協同工作的。

為什麼開發者需要懂密碼學？

簡單來說，是為了保護資料的三個核心特性，又稱為「CIA Triad」：

  1. 機密性 (Confidentiality)：確保只有授權的人才能讀取資料。就像把信件放進只有收信人有鑰匙的信箱。
  2. 完整性 (Integrity)：確保資料在傳輸或儲存過程中沒有被偷偷修改。就像在信封上貼一個特殊的封條，一旦被撕開就會留下痕跡。
  3. 可用性 (Availability)：確保授權使用者在需要時可以存取資料。雖然這與加密的關聯較間接，但不當的加密實現可能影響可用性。

當處理使用者密碼、API 金鑰、個人身份資訊 (PII) 或任何敏感資料時，密碼學是必需品。

類型一：對稱加密 (Symmetric Cryptography)

這是最直觀的加密方式，就像家裡的大門鑰匙，用同一把鑰匙上鎖和開鎖。

  • 核心概念：加密和解密使用同一把密鑰 (Secret Key)。
  • 優點：
    • 速度快：演算法計算開銷小，非常適合加密大量資料，如檔案、影片串流等。
  • 缺點：
    • 密鑰分發問題：最大的挑戰在於，如何安全地將這把唯一的密鑰交給對方？如果在傳遞過程中密鑰被攔截，那麼整個加密就失去了意義。

Python 實作：AES 加密

AES (Advanced Encryption Standard) 是目前最流行的對稱加密演算法。使用 Python 中最權威的 cryptography 函式庫來實作。

pip install cryptography

from cryptography.hazmat.primitives.ciphers import Cipher, algorithms, modes
from cryptography.hazmat.primitives import padding
from cryptography.hazmat.backends import default_backend
import os

# --- 準備工作 ---
# 1. 一把 32 bytes (256 bits) 的密鑰。在真實應用中，這應該來自安全的金鑰管理系統。
#    絕對不要硬編碼 (hardcode) 在程式碼裡
key = os.urandom(32)

# 2. 一個 16 bytes 的初始化向量 (IV)。IV 確保即使使用相同的密鑰加密相同的明文，
#    每次產生的密文也不同。IV 不需要保密，但每次加密都必須是唯一的。
iv = os.urandom(16)

# 3. 要加密的訊息 (必須是 bytes)
message = b"This is a secret message for symmetric encryption."

# --- 加密過程 ---
# 創建一個 AES Cipher 物件，使用 CBC 模式
cipher = Cipher(algorithms.AES(key), modes.CBC(iv), backend=default_backend())
encryptor = cipher.encryptor()

# PKCS7 填充，確保訊息長度是區塊大小的整數倍
padder = padding.PKCS7(algorithms.AES.block_size).padder()
padded_data = padder.update(message) + padder.finalize()

# 進行加密
ct = encryptor.update(padded_data) + encryptor.finalize()

print(f"原始訊息: {message.decode('utf-8')}")
print(f"加密後的密文 (Ciphertext): {ct.hex()}")

# --- 解密過程 ---
# 使用相同的 key 和 iv 進行解密
decryptor = cipher.decryptor()
decrypted_padded_data = decryptor.update(ct) + decryptor.finalize()

# 移除填充
unpadder = padding.PKCS7(algorithms.AES.block_size).unpadder()
decrypted_data = unpadder.update(decrypted_padded_data) + unpadder.finalize()

print(f"解密後的訊息: {decrypted_data.decode('utf-8')}")

assert message == decrypted_data

類型二：非對稱加密 (Asymmetric Cryptography)

為了解決對稱加密的密鑰分發問題，非對稱加密應運而生。它也被稱為公開金鑰加密 (Public-key Cryptography)。

  • 核心概念：使用一對數學上相關的密鑰：公鑰 (Public Key) 和 私鑰 (Private Key)。
    • 公鑰可以自由分發，任何人都可以擁有。
    • 私鑰必須嚴格保密，只有自己能持有。
    • 用公鑰加密的資料，只能用對應的私鑰解密。
  • 優點：
    • 解決了密鑰分發問題：可以把公鑰給任何人，他們用公鑰加密訊息後傳給你，只有擁有私鑰的你才能解開。
    • 可用於數位簽章：反過來，用私鑰加密（簽章）的內容，可以用公鑰驗證，證明訊息確實來自你。
  • 缺點：
    • 速度非常慢：計算複雜度遠高於對稱加密，不適合用來加密大量資料。

Python 實作：RSA 加密

RSA 是最廣為人知的非對稱加密演算法。

from cryptography.hazmat.primitives import hashes
from cryptography.hazmat.primitives.asymmetric import rsa, padding

# --- 準備工作：產生金鑰對 ---
# 在真實應用中，金鑰對應該只產生一次並妥善保存
private_key = rsa.generate_private_key(
    public_exponent=65537,
    key_size=2048,
)
public_key = private_key.public_key()

# 2. 要加密的訊息
message = b"A secret message for asymmetric encryption."

# --- 加密過程 (使用公鑰) ---
ciphertext = public_key.encrypt(
    message,
    padding.OAEP(
        mgf=padding.MGF1(algorithm=hashes.SHA256()),
        algorithm=hashes.SHA256(),
        label=None
    )
)

print(f"原始訊息: {message.decode('utf-8')}")
print(f"加密後的密文 (Ciphertext): {ciphertext.hex()}")


# --- 解密過程 (使用私鑰) ---
plaintext = private_key.decrypt(
    ciphertext,
    padding.OAEP(
        mgf=padding.MGF1(algorithm=hashes.SHA256()),
        algorithm=hashes.SHA256(),
        label=None
    )
)

print(f"解密後的訊息: {plaintext.decode('utf-8')}")

assert message == plaintext

類型三：雜湊函式 (Hashing)

雜湊與加密不同，它是一個單向的過程，無法逆向還原。它就像是為資料產生一個獨一無二的「數位指紋」。

  • 核心概念：將任意長度的輸入，轉換成一個固定長度的輸出（雜湊值）。
  • 特性：
    1. 不可逆性：無法從雜湊值反推出原始輸入。
    2. 確定性：相同的輸入永遠會得到相同的輸出。
    3. 雪崩效應：輸入的微小改變會導致輸出的巨大差異。
  • 用途：
    • 密碼儲存：永遠不要直接儲存使用者的明文密碼 應該儲存密碼經過加鹽 (Salting) 後的雜湊值。驗證時，將使用者輸入的密碼用同樣的方式雜湊，再比對雜湊值是否相符。
    • 資料完整性驗證：下載檔案時常見的 SHA256 校驗碼，就是用來確保檔案在下載過程中沒有被竄改或損壞。

Python 實作：SHA-256 雜湊

Python 內建的 hashlib 函式庫可以輕鬆實現。

import hashlib

# 建立一個 SHA-256 hash 物件
hasher = hashlib.sha256()

# 餵入要雜湊的資料 (必須是 bytes)
message1 = b"Hello, world!"
hasher.update(message1)

# 取得雜湊值的十六進位表示
hash1 = hasher.hexdigest()
print(f"'{message1.decode()}' 的 SHA-256 雜湊值: {hash1}")

# 再次計算，證明其確定性
hasher2 = hashlib.sha256()
hasher2.update(message1)
assert hash1 == hasher2.hexdigest()

# 稍微修改輸入，觀察雪崩效應
message2 = b"Hello, World!" # W 大寫
hasher3 = hashlib.sha256()
hasher3.update(message2)
hash3 = hasher3.hexdigest()
print(f"'{message2.decode()}' 的 SHA-256 雜湊值: {hash3}")

優缺點比較與協同工作

類型 主要用途 金鑰 速度 核心優點 核心缺點
對稱加密 資料機密性 (大量) 單一密鑰 快 效能高，適合加密檔案/串流 密鑰分發困難
非對稱加密 金鑰交換、數位簽章 公鑰/私鑰對 慢 安全的金鑰交換 效能低，不適合加密大量資料
雜湊 資料完整性、密碼儲存 無金鑰 極快 單向不可逆，驗證快速 不能用於資料機密性

現實世界中的完美結合：混合加密系統 (Hybrid Cryptosystem)**

這三者並非互相排斥，而是相輔相成。現代網路安全通訊的基石 TLS/SSL (HTTPS) 就是一個典型的混合加密應用：

  1. 非對稱加密：瀏覽器和伺服器先用非對稱加密（如 RSA）來安全地協商出一把一次性的對稱密鑰。
  2. 對稱加密：一旦雙方都擁有了這把共享的對稱密鑰，後續所有的應用資料（瀏覽的網頁內容）都將使用這把密鑰進行對稱加密（如 AES），因為它速度快。
  3. 雜湊：通訊過程中會使用雜湊函式（如 HMAC）來確保每個訊息的完整性，防止被中間人竄改。

結論

  1. 不要自己發明加密演算法：使用經過業界多年驗證的標準演算法（AES, RSA, SHA-256 等）。
  2. 使用成熟的函式庫：像 Python 的 cryptography 函式庫已經處理了許多底層的複雜細節和安全陷阱。
  3. 理解所用的工具：知道何時該用對稱加密，何時該用非對稱加密，以及為何要對密碼進行雜湊。
  4. 金鑰管理是核心：演算法再強，金鑰洩漏了也無濟於事。學習如何安全地儲存和管理密鑰。

密碼學是一個深邃的領域，但掌握其在軟體開發中的基本應用，是每位現代開發者保護自己產品和使用者的必備技能。
